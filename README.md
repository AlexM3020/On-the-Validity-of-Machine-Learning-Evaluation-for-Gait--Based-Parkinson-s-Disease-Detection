# Subject-Independent Evaluation of Mamba for Parkinson's Disease Detection from Gait Signals

Code accompanying **Subject-Independent Evaluation of Mamba for Parkinson's Disease Detection from Gait Signals**.

This work studies binary Parkinson's disease classification from multichannel gait signals using a compact Mamba sequence classifier, with LSTM and GRU baselines. Its central evaluation principle is **participant independence**: all recordings and windows from the same participant must remain in one partition. Splitting recording files alone is insufficient when participants have multiple recordings.

The repository provides data preparation, participant-level splitting, three classifiers, training, checkpoint evaluation, and automated tests. It contains no manuscript, raw dataset, or pretrained weights.

## Method

**18 gait channels → linear projection → layer normalization → two residual Mamba blocks → masked temporal max pooling → binary classification head.**

Default settings are sequence length 2,000, model width 128, state size 32, convolution width 32, and expansion factor 2. Layer normalization follows each residual block. Padding is excluded from pooling. LSTM and GRU baselines use two bidirectional recurrent layers and concatenate the final valid forward/backward states.

The input pipeline:

1. Identifies participants from complete study-qualified identifiers such as `GaCo01`, `JuCo01`, and `SiPt02`.
2. Stratifies **participants**, not recordings or windows, into training and validation; an optional held-out test partition is supported.
3. Applies per-recording, per-channel z-score normalization, without fitting statistics across participants.
4. Creates nonoverlapping fixed-length windows **after splitting**. Incomplete trailing windows of long recordings are discarded; short recordings produce one masked, zero-padded window.
5. Saves participant membership, recording hashes, and window boundaries alongside each run.

`Co` denotes control (class 0); `Pt` denotes Parkinson's disease (class 1). Metrics are per window: sample support is not a participant count.

## Results reported in the paper

| Model | Accuracy | Macro-F1 | Scored samples |
| :--- | ---: | ---: | ---: |
| Mamba | 88.61% | 88.52% | 790 |
| LSTM | 87.18% | 87.16% | 390 |
| GRU | 84.36% | 84.34% | 390 |

These are the existing validation results used in the paper, not scores generated by this release. Validation informed model selection and early stopping; unequal supports do not establish a matched head-to-head comparison or statistical superiority.

The released workflow is a clean implementation of the documented design and participant-independent evaluation protocol. The exact historical generating revision and split manifests were not retained, so running it is **not a guarantee of reproducing those numbers**. The baselines share a common input and training interface for controlled new comparisons; they do not recreate every historical baseline setting.

## Installation

Use Python 3.10 or later. A virtual environment is recommended.

```bash
python -m venv .venv
# Linux / WSL
source .venv/bin/activate
# Windows PowerShell instead: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### Mamba backend

Mamba requires **Linux or WSL, an NVIDIA GPU, CUDA-enabled PyTorch, and a compatible CUDA build toolchain**. Install the appropriate CUDA-enabled PyTorch distribution before the Mamba extension:

```bash
python -m pip install --no-build-isolation -r requirements-mamba.txt
```

The default width-32 convolution uses PyTorch's depthwise convolution and the real Mamba selective-scan CUDA operation. The optional `causal-conv1d` extension is not required: its optimized small-width kernels cannot implement width 32. No substitute CPU Mamba backend is used.

LSTM and GRU run on CPU or CUDA and do not require `mamba-ssm`.

## Dataset

Obtain the [Gait in Parkinson's Disease dataset from PhysioNet](https://physionet.org/content/gaitpdb/1.0.0/) under its applicable terms. Place gait signal text files in a local directory; subdirectories are supported. Downloading is not automatic.

Supported filenames include `GaCo01_01.txt`, `GaPt01_01.txt`, and similarly named `Ju` and `Si` recordings. Prepared files with numeric chunk suffixes, such as `GaCo01_01_chunk_1.txt`, retain participant identity. Duplicate basenames are rejected rather than silently merged. Metadata text files are ignored.

The default input is a whitespace-separated matrix with **time in column 0 and 18 force channels in columns 1–18**. Indices are zero-based. Change them with `--channels` for a different documented layout. Malformed matrices and nonfinite values raise errors rather than silently excluding participants.

Supply original recordings or prepared inputs whose processing has not mixed participants across partitions. This workflow performs no oversampling or augmentation; externally prepared data must preserve participant lineage.

## Training

Run commands from the repository root. Each run requires a new, empty output directory; existing results are never overwritten.

### Mamba

```bash
python train.py --model mamba --data-dir data/raw --output-dir outputs/mamba --device cuda
```

Defaults use an 80/20 participant-level training/validation split, seed 42, Adam with learning rate `5e-5`, batch size 64, class weights `[1.1, 1.0]`, up to 100 epochs, early-stopping patience 10, and learning-rate reduction on validation-loss plateaus with patience 5.

### Recurrent baselines

```bash
python train.py --model lstm --data-dir data/raw --output-dir outputs/lstm --device cpu
python train.py --model gru --data-dir data/raw --output-dir outputs/gru --device cpu
```

All models share CLI defaults unless overridden. For a controlled comparison, keep inputs, partition seed, sequence length, and scoring unit fixed; select model-specific hyperparameters using validation data only.

### Optional held-out test evaluation

```bash
python train.py --model mamba --data-dir data/raw --output-dir outputs/mamba_test --device cuda --validation-fraction 0.2 --test-fraction 0.2
```

This assigns approximately 60/20/20 percent of participants to training/validation/test, with class stratification. Only validation determines early stopping and checkpoint selection. Test evaluation occurs after selecting the best checkpoint. This option is for new experiments, not a test result reported above.

Inspect configurable settings:

```bash
python train.py --help
```

## Outputs and checkpoint evaluation

Each run produces:

- Configuration and a hash-verified participant/window split manifest.
- A best-validation checkpoint containing model state, configuration, and split provenance—not an arbitrary serialized model object.
- Per-epoch training/validation loss, accuracy, and learning rate, plus a loss-curve image.
- Validation metrics, confusion matrix, and per-window predictions; equivalent test outputs when requested.

Evaluate a checkpoint from this release without training:

```bash
python train.py --data-dir data/raw --output-dir outputs/evaluation --checkpoint outputs/mamba/best_model.pt --partition validation --device cuda
```

Use `--partition test` only for checkpoints created with a test partition. Evaluation restores model/preprocessing settings and verifies filenames, file contents, participants, and window boundaries. Changed data or mismatched splits are rejected. Only load trusted checkpoints; restricted state loading is not a general security guarantee.

## Tests

```bash
python -m unittest discover -s tests -v
```

Tests cover repeated-recording grouping, disjoint participants, stratification, normalization, padding, CPU forward/backward passes, checkpoint evaluation, and rejection of changed inputs. Mamba architecture/scan-interface tests use explicitly identified test doubles; they do not certify real CUDA execution. CPU preprocessing and end-to-end LSTM/GRU workflows have been exercised on synthetic data. No new dataset training or predictive results were produced while preparing this release.

## Scope

Research software, not a diagnostic system. Participant separation prevents one important form of leakage but does not establish cross-cohort robustness, clinical validity, or independence of externally prepared data. Seeds and manifests aid repeatability; numerical identity across hardware/CUDA versions is not guaranteed.
